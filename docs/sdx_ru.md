# sdx

[English](sdx.md) | Русский

`sdx` — командная строка Seedex. Она построена вокруг четырёх сервисов —
`router`, `vpn`, `proxy`, `dns` — плюс `link`, связь с вашими серверами, и
везде читается одинаково:

```
sdx                         статус коробки
sdx <service>               статус одного сервиса
sdx <service> <action>      одно действие над одним сервисом
sdx <action>                то же действие над каждым сервисом, у которого оно есть
sdx <service> help          действия этого сервиса
```

Изменения, сделанные через `sdx`, — добавление, удаление, включение,
правка, настройки — ожидают `sdx apply`, который сохраняет их и
перезапускает сервис; `sdx revert` их отбрасывает, `sdx changes`
показывает. Каждая команда работает с одним сервисом (`sdx vpn apply`) или
со всеми. Под капотом это обычный UCI: `uci changes`, `uci commit`, и
`restart` тоже подхватывает ожидающие изменения. В LuCI каждая страница
показывает свои несохранённые изменения с кнопками Apply и Revert; штатный
Save & Apply OpenWrt их не видит.

Записи — конфиги VPN и proxy, правила router — адресуются по имени или по
номеру в списке `show`; `show`, `enable`, `disable` и `remove` принимают
несколько сразу.

## Каждый сервис

### `sdx <service> start` / `stop` / `restart`

Управление сервисом прямо сейчас. Без сервиса — `sdx restart` — все четыре
останавливаются и поднимаются в правильном порядке: сначала DNS, потом
туннели, потом router, когда туннель поднялся.

### `sdx <service> changes` / `apply` / `revert`

Ожидающие изменения сервиса: показать, сохранить и перезапустить сервис,
чтобы они вступили в силу, или отбросить. `apply` также перезапускает
сервис, который работает с более старыми настройками, чем сохранённые.

### `sdx <service> enable` / `disable`

Поднимается ли сервис при загрузке. `disable` заодно останавливает его
сейчас, `enable` — запускает; выключенный сервис показывает `disabled` в
статусе. Без имени после `enable` или `disable` действие относится к
сервису, с именем — к его записи.

## Коробка

### `sdx`

Статус всего: аплинк, какой туннель несёт трафик и его RTT, каждый сервис по
очереди и связи с вашими серверами.

### `sdx import <path>`

Импорт файла конфига — `.conf` AmneziaWG для `vpn`, `.json` sing-box для
`proxy`, `.json` правил для `router` — или всех конфигов из каталога. Файл
сам определяет, к какому сервису относится; имя файла становится именем
записи, занятое имя отклоняется. С сервером на seedex-agent файлы носить не
нужно: см. [Link](#link).

### `sdx logs`

Строки Seedex из системного лога. Аргументы передаются в `logread`, так что
`sdx logs -f` следит за логом.

### `sdx version`

Версия установленного пакета.

## VPN

Туннели AmneziaWG. Каждый импортированный конфиг становится отдельным
туннелем; router пробует все и ведёт трафик через самый быстрый живой, так что
несколько конфигов — это резервирование, а не выбор.

### `sdx vpn`

Работает ли сервис и каждый конфиг с его состоянием: несущий трафик отмечен
`[*]`, доступные показывают RTT, выключенные так и подписаны.

### `sdx vpn show [name ...]`

Без имени — конфиги с интерфейсом туннеля и файлом. С именами — детали
каждого конфига и содержимое его файла.

### `sdx vpn enable <name ...>` / `disable <name ...>`

Включить или выключить конфиги, не удаляя. Выключенный конфиг сохраняет
файл и возвращается по `enable`.

### `sdx vpn remove <name ...>`

Удалить конфиги. Их файлы удаляются при следующем запуске сервиса.

### `sdx vpn export`

Напечатать все файлы конфигов в виде, который принимает `sdx import`, — так
конфиги переносят на другой роутер.

### `sdx vpn reset`

Остановить сервис и удалить все конфиги вместе с файлами.

## Proxy

Туннель sing-box. Каждый импортированный конфиг отдаёт свои outbound-ы одному
экземпляру sing-box, который сам выбирает лучший по URL-тесту; router видит
результат как один туннель рядом с VPN-ными.

### `sdx proxy`

Работает ли сервис и каждый конфиг: outbound, который sing-box использует
сейчас, показывает RTT туннеля и отмечен `[*]`, когда router ведёт трафик
через proxy.

### `sdx proxy show [name ...]`

Без имени — конфиги с файлами. С именами — outbound-ы каждого конфига.

### `sdx proxy enable <name ...>` / `disable <name ...>`

Включить или выключить конфиги. sing-box пересобирается из включённых при
следующем перезапуске.

### `sdx proxy remove <name ...>`

Удалить конфиги. Их файлы удаляются при следующем запуске сервиса.

### `sdx proxy config`

Настройки сервиса: `show` перечисляет их, `get <key>` печатает одну,
`set key=value ...` меняет.

- `log_level` — подробность sing-box: `error`, `warn`, `info`, `debug`, `trace`.
- `urltest_interval` — как часто sing-box перемеряет outbound-ы, например `1m`.

### `sdx proxy export`

Напечатать все файлы конфигов в виде, который принимает `sdx import`.

### `sdx proxy reset`

Остановить сервис и удалить все конфиги вместе с файлами.

## Router

Политика: куда идёт трафик, когда ни одно правило не совпало, и правила,
которые делают исключения. Watchdog пробует каждый туннель и держит overlay
на самом быстром живом; kill switch отбрасывает трафик, предназначенный для
overlay, когда ни один туннель не поднят, вместо того чтобы выпустить его к
провайдеру.

У правила есть `type` — что происходит с совпавшим трафиком:

- `overlay` — через туннель
- `direct` — напрямую к провайдеру
- `block` — домены перестают резолвиться, пакеты к IP отбрасываются

и оно совпадает либо по назначению (`domain`, `ip`, список), либо по
устройству (`client_mac`, `client_ip`), но не по обоим. Правила по устройству сильнее правил по
назначению, так что устройство, закреплённое за `direct`, остаётся direct даже
для доменов, которые другие правила отправляют в туннель.

### `sdx router`

Работает ли сервис, режим маршрутизации, kill switch, интервал watchdog и
правила с их типом и тем, что они матчат.

### `sdx router show [name ...]`

Без имени — правила. С именами — все поля каждого правила.

### `sdx router add <name> type=... [matchers]`

Добавить правило. Матчеры, каждый сколько угодно раз:

- `domain=<domain>` — домен и его поддомены
- `ip=<address or CIDR>`
- `list_url=<url>` — текстовый файл с доменом или IP на строку, загружается
  при старте сервиса и затем каждые `list_refresh` (например `12h`, `1d`);
  файлы в формате hosts (`0.0.0.0 domain`) принимаются как есть
- `list_path=<file>` — то же из файла на роутере
- `client_mac=<aa:bb:cc:dd:ee:ff>` — каждый пакет от этого устройства
- `client_ip=<address or CIDR>` — каждый пакет с этого адреса или подсети:
  гостевой VLAN, устройство со статическим адресом, клиент за другим
  роутером, чей MAC не виден

```sh
sdx router add youtube type=overlay domain=youtube.com domain=googlevideo.com
sdx router add ads type=block list_url=https://raw.githubusercontent.com/StevenBlack/hosts/master/hosts list_refresh=1d
sdx router add tv type=direct client_mac=aa:bb:cc:dd:ee:ff
sdx router add guests type=direct client_ip=10.0.20.0/24
```

### `sdx router update <name> ...`

Изменить правило: `type=`, `name=`, опции списка, а для матчеров
`domain=` / `del-domain=` / `clear-domains`, `ip=` / `del-ip=` / `clear-ips`,
`client_mac=` / `del-client_mac=` / `clear-client_macs`,
`client_ip=` / `del-client_ip=` / `clear-client_ips`.

### `sdx router enable <name ...>` / `disable <name ...>`

Включить или выключить правила.

### `sdx router remove <name ...>`

Удалить правила.

### `sdx router config`

Настройки сервиса: `show`, `get <key>`, `set key=value ...`.

- `default_route` — куда идёт несовпавший трафик: `overlay` или `direct`.
- `kill_switch` — `1` отбрасывает трафик для overlay, когда ни один туннель
  не поднят, `0` пускает его к провайдеру.
- `watchdog_interval` — секунды между пробами туннелей.
- `watchdog_url` — что пробы запрашивают.
- `watchdog_timeout` — секунды, после которых проба считается неудачной.

### `sdx router export`

Напечатать правила в JSON, который принимает `sdx import`.

### `sdx router reset`

Остановить сервис и удалить все правила.

## DNS

Резолвер всей сети. Запросы уходят зашифрованными и через туннель, когда он
поднят; устройствам, которые пытаются резолвить сами, всё равно отвечает
роутер.

### `sdx dns`

Работает ли сервис, upstream, резолвер и включён ли перехват.

### `sdx dns config`

Настройки сервиса: `show`, `get <key>`, `set key=value ...`.

- `upstream` — куда роутер отправляет запросы: `encrypted` (DNS-over-HTTPS к
  резолверу; через туннель, когда он есть, иначе по линии провайдера),
  `plain` (классический DNS резолвера, тем же путём) или `provider` (то, что
  выдал провайдер, без изменений).
- `resolver` — `cloudflare`, `quad9` или `google`; с `provider` не
  используется.
- `intercept` — `1` перенаправляет каждый DNS-запрос из сети в роутер и
  отклоняет DNS-over-TLS, так что устройство со своим резолвером всё равно
  следует правилам; `0` не трогает устройства.

## Link

Связь с сервером, на котором стоит
[seedex-agent](https://github.com/aggnostos/seedex-agent). Соединитесь один
раз, и дальше роутер сам забирает конфиги VPN и proxy с сервера — каждые 30
минут и по запросу, — так что новый клиент, ротированные учётные данные или
новый протокол на сервере доходят до роутера без копирования. Конфиги,
которые принёс link, — обычные записи `vpn` и `proxy`, помеченные как
управляемые этим link-ом: link их обновляет, удаляет, когда сервер их убрал,
а импортированные вручную не трогает.

### `sdx link`

Все связи: удалась ли последняя синхронизация, URL, сколько конфигов
управляется и когда синхронизировались в последний раз.

### `sdx link add <name> <url> <token> <fingerprint>`

Соединиться с сервером. `sdx link add <router>` на сервере печатает URL,
токен, отпечаток сертификата и точную команду для вставки здесь. Отпечаток
закрепляет сертификат сервера, так что никто посередине не выдаст себя за
него; токен идентифицирует этот роутер. Соединение сразу импортирует все
конфиги, которые сервер предлагает.

### `sdx link show <name>`

Что сервер предлагает прямо сейчас, по сервисам, с `[*]` у конфигов,
которые роутер импортировал.

### `sdx link select <name> <config> ... | --all`

Выбрать, какие из предложенных конфигов импортировать, — роутеру не
обязательно нести всех клиентов, которых знает сервер. Выбор запоминается и
применяется сразу: невыбранные конфиги удаляются, вновь выбранные
добавляются. `--all` возвращает импорт всего — так по умолчанию после `add`.

### `sdx link sync [name]`

Забрать сейчас, для одной связи или всех. Изменившиеся конфиги заменяются,
новые добавляются, убранные удаляются, изменившиеся сервисы
перезапускаются. Cron запускает это каждые 30 минут.

### `sdx link remove <name>`

Разорвать связь и удалить все конфиги, которые она принесла.
